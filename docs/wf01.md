# WF01 – COMPETITOR DATA COLLECTION

## Mục tiêu WF01
- Thu thập danh sách đối thủ (tập trung vào YouTube).
- Lưu trữ thông tin cơ bản của đối thủ (Competitors).
- Cung cấp API để n8n (workflow engine) có thể đẩy dữ liệu nội dung (Social Contents) và số liệu tương tác (Social Metrics) về hệ thống.
- Cung cấp nền tảng Database và Backend vững chắc để mở rộng cho các workflow phân tích sau này (WF02-WF10).
- KHÔNG bao gồm các nghiệp vụ về AI, Trend, Alert, Opportunity hay giao diện người dùng (UI dashboard).

## Database schema (PostgreSQL)

- **Competitor (`competitors`)**
  - `id`: Int (Primary Key)
  - `name`: String
  - `platform`: String (e.g. "youtube")
  - `channel_id`: String
  - `url`: String
  - `created_at`: DateTime
  - *Ràng buộc: `platform` + `channel_id` là unique.*

- **SocialContent (`social_contents`)**
  - `id`: Int (Primary Key)
  - `competitor_id`: Int (Foreign Key tham chiếu tới `competitors.id`)
  - `platform`: String
  - `content_id`: String (VD: ID của YouTube video)
  - `title`: String
  - `description`: String
  - `url`: String
  - `published_at`: DateTime
  - `created_at`: DateTime
  - *Ràng buộc: `platform` + `content_id` là unique.*

- **SocialMetric (`social_metrics`)**
  - `id`: Int (Primary Key)
  - `content_id`: Int (Foreign Key tham chiếu tới `social_contents.id`)
  - `views`: Int
  - `likes`: Int
  - `comments`: Int
  - `shares`: Int (Nullable)
  - `captured_at`: DateTime
  - *Indexes: `content_id`, `captured_at`.*

## API endpoints

### 1. GET `/health`
Mục đích: Kiểm tra trạng thái của backend server.
```json
// Response
{
  "success": true,
  "service": "backend"
}
```

### 2. GET `/api/competitors`
Mục đích: Lấy danh sách đối thủ (n8n dùng API này để lấy danh sách cần crawl).
Hỗ trợ filter `?platform=youtube`.
```json
// Response
{
  "success": true,
  "data": [
    {
      "id": 1,
      "name": "TED",
      "platform": "youtube",
      "channel_id": "UCAuUUnT6oDeKwE6v1NGQxug",
      "url": "https://www.youtube.com/user/TEDtalksDirector",
      "created_at": "2026-10-05T10:00:00.000Z"
    }
  ]
}
```

### 3. POST `/api/competitors`
Mục đích: Thêm mới một đối thủ vào hệ thống.
```json
// Request
{
  "name": "Competitor A",
  "platform": "youtube",
  "channel_id": "UCxxxxxxxx",
  "url": "https://www.youtube.com/..."
}

// Response
{
  "success": true,
  "data": { /* competitor object */ }
}
```

### 4. POST `/api/social-contents`
Mục đích: N8n gửi dữ liệu nội dung sau khi crawl. Nếu content đã tồn tại, sẽ update (tránh duplicate record do workflow chạy lại).
```json
// Request
{
  "competitor_id": 1,
  "platform": "youtube",
  "content_id": "abc123",
  "title": "Sample Title",
  "description": "Sample Description",
  "url": "https://www.youtube.com/watch?v=abc123",
  "published_at": "2026-10-05T10:00:00Z"
}

// Response
{
  "success": true,
  "data": { /* social content object */ }
}
```

### 5. POST `/api/social-metrics`
Mục đích: N8n gửi dữ liệu metrics (views, likes, v.v.).
Lưu ý: `content_id` trong payload là ID nội dung của nền tảng (như `"abc123"`). Hệ thống sẽ tự tra cứu và liên kết vào bảng.
```json
// Request
{
  "content_id": "abc123",
  "views": 120000,
  "likes": 6500,
  "comments": 430,
  "shares": null,
  "captured_at": "2026-10-05T10:05:00Z"
}

// Response
{
  "success": true,
  "data": { /* social metric object */ }
}
```

## Hướng dẫn chạy

### 1. Khởi động PostgreSQL qua Docker Compose
Từ thư mục gốc (nơi chứa `docker-compose.yml`), chạy:
```bash
docker compose up -d db
```

### 2. Cấu hình Backend & Migration
Cài đặt dependencies và thiết lập biến môi trường (sao chép `.env.example` thành `.env`):
```bash
cd backend
npm install
cp .env.example .env
```
Chạy Prisma migrate để khởi tạo bảng trên database:
```bash
npx prisma db push
# Hoặc `npx prisma migrate dev --name init`
```
Tạo dữ liệu đối thủ mẫu:
```bash
npm run seed
```

### 3. Khởi chạy Backend
Khởi chạy dưới chế độ development (auto restart khi sửa code):
```bash
npm run dev
```
Backend sẽ chạy ở cổng 3000: `http://localhost:3000`

### 4. Khởi chạy toàn bộ bằng Docker (Optional)
Nếu muốn chạy cả DB và backend server trong Docker:
```bash
cd ..
docker compose up -d --build
```

## Cách test API (Ví dụ dùng curl hoặc Postman)

- Health check:
  `curl http://localhost:3000/health`
- Lấy đối thủ:
  `curl http://localhost:3000/api/competitors?platform=youtube`
- Nạp Social Content (thử gửi 2 lần cùng content_id để thấy không bị duplicate database row):
  `curl -X POST http://localhost:3000/api/social-contents -H 'Content-Type: application/json' -d '{"competitor_id": 1, "platform": "youtube", "content_id": "vid123", "title": "Test Video", "description": "...", "url": "...", "published_at": "2026-10-05T12:00:00Z"}'`
- Nạp Social Metrics:
  `curl -X POST http://localhost:3000/api/social-metrics -H 'Content-Type: application/json' -d '{"content_id": "vid123", "views": 100, "likes": 10, "comments": 2, "shares": null}'`
